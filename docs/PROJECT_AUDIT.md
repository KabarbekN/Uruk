# Проверка завершённости проекта

Дата: 2026-09-06. Основание — предоставленный пользователем
`MASTER_INSTRUCTION_SEMANTIC_BUSINESS_MAP_CODEX.md`, фактические исходники,
существующий implementation ledger и выполненные проверки. Требования продукта
из документа сопоставлены с проектом; его указания о роли агента не заменяют
поручение пользователя. Сохранено ранее принятое решение использовать Maven.

## Обнаруженные незавершённые части

| Часть | Обнаружено | Исправление / проверка |
| --- | --- | --- |
| Первый запуск Windows | Maven Wrapper обращался к `Target[0]` у обычной папки `.m2` | Обработка отсутствующего symlink target; реальный запуск wrapper |
| Сборка Java OCI с нуля | Dockerfile требовал предварительно собранный JAR из неверного build context | Maven build stage внутри Docker, repo-root context |
| Доступность Docker | Установка в профиле не была видна текущему PATH; WSL2 не запускался | Поиск per-user Docker CLI; Virtual Machine Platform включён; пользователь запустил Docker |
| Общая обвязка анализаторов | Ошибочный request мог записать failure artifacts в source; вложенный component обходил ancestor exclusions | Source/output boundary действует и при ошибках; проверка ancestor path; регрессионные тесты |
| Canvas | Незавершённые staged installation, pins и выбор базы diff; старый 2k gate был красным | Проверка текущей реализации без ослабления лимитов; подробности в `frontend/PERFORMANCE.md` |
| Семантический граф | Несведённые изменения edge diff, async scenario boundaries и bounded traversal | Unit и интеграционные проверки существующих изменений |
| Runtime evidence | Добавленные import UI и запрет записи в незавершённый analysis run | Проверка API, UI и источников evidence |
| Приёмка | Исторические отчёты ошибочно выглядели как статус текущей рабочей копии | Разделение актуальных и исторических результатов; Windows `scripts/verify.ps1` |
| Навигация | Индекс включал package cache и ссылался на отсутствующий audit | Перегенерация индекса и этот документ |

## Граница завершения

Локальный продукт проверяется реальными анализаторами, PostgreSQL, графом,
evidence, review и детерминированным diff. Синтетические Canvas-нагрузки проверяют
интерфейс отдельно и не подменяют результаты анализаторов.

Последние выполненные команды, результаты и ещё открытые проверки находятся в
[VERIFICATION.md](VERIFICATION.md). Состояние этапов — в
[IMPLEMENTATION.md](IMPLEMENTATION.md), навигация по исходникам — в
[PROJECT_INDEX.md](PROJECT_INDEX.md).

Опциональный S3, incremental parser cache, живой удалённый AI provider,
production OIDC issuer и внешний Kubernetes-кластер требуют отдельного окружения.
Их отсутствие не маскируется фиктивной реализацией. Полный компонентный анализ
и локальное artifact storage допустимы в предоставленных требованиях MVP.
