# Semantic Business Map: локальный запуск

Приложение: [http://127.0.0.1:8088](http://127.0.0.1:8088).
Требуется запущенный Docker Desktop в режиме Linux containers.

## Запуск

В PowerShell из папки проекта:

```powershell
.\scripts\dev.ps1
```

Для первой сборки, включая образы всех анализаторов:

```powershell
.\scripts\dev.ps1 -Build
```

Скрипт задаёт путь к артефактам и запускает PostgreSQL, API, worker и интерфейс.
Java-сборка использует Maven. Gradle не требуется. AI по умолчанию выключен;
ключи внешнего провайдера для анализа исходников не нужны.

## Первый Анализ

1. Откройте приложение и выберите русский язык в переключателе языка.
2. Создайте проект с путём `/repository/fixtures/spring-order-service`.
3. Запустите анализ и дождитесь его завершения.
4. Откройте бизнес-карту, выберите правило с `MINIMUM_AMOUNT` и проверьте исходник
   в панели доказательств. Исходный порог равен `500`.
5. Подтвердите правило через ручную проверку.
6. Измените путь репозитория проекта на
   `/repository/fixtures/spring-order-service-revision2` и запустите следующий
   анализ с предыдущим результатом в качестве базы сравнения.
7. В семантическом сравнении проверьте изменение `500` на `300` и устаревание
   прежнего подтверждения.

В представлении владения данными доступны разобранные SQL defaults и trigger.
Для отдельного примера TypeScript/NestJS используйте путь
`/repository/analyzers/typescript-node/tests/fixtures`.
Это тестовые исходные репозитории: их результаты создаются настоящими
анализаторами, а не подставляются интерфейсом.

## Что Означает Частичный Результат

В безопасном статическом режиме система не запускает сборку анализируемого
проекта и не загружает его зависимости. Неизвестные внешние вызовы и
неподдерживаемые конструкции остаются диагностикой. Поэтому корректный анализ
примера может завершиться статусом `PARTIALLY_SUCCEEDED`.

Проверяйте покрытие, диагностику и источник конкретного утверждения.
Факты анализаторов, выводы правил, текст AI и решения человека хранятся отдельно.
Ручное подтверждение не изменяет исходный факт.

## Данные И Остановка

PostgreSQL хранится в Docker volume, артефакты в `.runtime/artifacts`.
Обычная остановка сохраняет данные:

```powershell
docker compose stop
```

Не используйте `docker compose down -v`, если хотите сохранить базу.
Не публикуйте порты текущей локальной конфигурации в интернет.

## Перед Внешним Размещением

Локальный worker имеет доступ к Docker socket. Это конфигурация разработки,
а не изолированный многопользовательский хостинг. Для внешней эксплуатации
нужны доверенный OIDC-провайдер, секреты, резервное копирование и изолированный
runner. Kubernetes adapter и манифесты есть, но живой кластер здесь не проверялся.
