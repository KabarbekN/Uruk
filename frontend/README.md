# Semantic Business Map Frontend

Vite, React, strict TypeScript, React Router, TanStack Query, Zustand, React Flow,
ELK in a Web Worker, Monaco, Zod, Vitest/RTL, and Playwright. There is no runtime
demo-data path. An API failure remains an error; an empty response remains empty.

## Run

Requires Node 24.19.0 and pnpm 10.27.0 (pinned in `packageManager`).

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

The development URL is http://127.0.0.1:5173. Vite proxies `/api` to
http://127.0.0.1:8080. Start the parent API/worker separately. Create a project
first; the optional Spring fixture button enters the real local repository path
`fixtures/spring-order-service`. It does not substitute analysis results.

```sh
pnpm generate:api
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e
pnpm format:check
```

Windows Playwright uses installed Chrome; Linux uses Playwright Chromium.
Override with `PLAYWRIGHT_CHANNEL` when needed. After `pnpm build`, set
`PLAYWRIGHT_PRODUCTION=true` to run acceptance against production preview on
port 5174. `PLAYWRIGHT_BASE_URL` selects an already running server and prevents
Playwright from starting another server. The build allowlist permits only
esbuild's required native-binary setup.

## Parent Integration

Build the image from the repository root:

```sh
docker build -f frontend/Dockerfile -t semantic-map-frontend .
```

The Dockerfile copies `docs/api-contract.yaml` into `/app/docs`, installs the
frontend's frozen pnpm lockfile, regenerates API types, and bundles the SPA.
The runtime uses the current stable nginx 1.30.4 Alpine 3.24 slim official image,
pinned by digest, then applies signed Alpine package updates with
`apk upgrade --no-cache`. For future security refreshes, rebuild with Docker's
`--no-cache` flag so the package-upgrade layer is not reused. Parent-owned image
scanning remains a separate release gate.
Its nginx stage proxies `/api/` and `/actuator` to `platform-api:8080`, disables
SSE buffering, preserves authorization and Last-Event-ID headers, and provides
SPA fallback. Source snippets, Monaco workers, and layout workers are served
locally; no editor CDN is used.

`../docs/api-contract.yaml` is the source of truth. `src/shared/api/generated.ts`
is generated by openapi-typescript and must not be edited manually. `types.ts`
only aliases generated schemas/operations; Zod validates untrusted responses.

All request paths below are relative to `/api/v1`:

| Workflow    | Requests and payload                                                                                                                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Projects    | `GET /projects` returns an array. `POST /projects` and `PATCH /projects/{id}` send `{name,description,repositoryPath}`. Name max 120; description/path max 2000.                                                                                                  |
| Archive     | `DELETE /projects/{id}`. UI explains access removal and preservation of immutable audit/history.                                                                                                                                                                  |
| Repository  | `POST /projects/{id}/repositories` with `{url,branch}`.                                                                                                                                                                                                           |
| Runs        | `GET /projects/{id}/analysis-runs`; `POST` same path with `{ref?,baselineRunId?}`. Baselines are restricted to `SUCCEEDED` and `PARTIALLY_SUCCEEDED`.                                                                                                             |
| Run state   | `GET /analysis-runs/{id}`; `POST /analysis-runs/{id}/cancel`. Progress is 0-100. Active runs poll every 3 seconds.                                                                                                                                                |
| Live events | `GET /analysis-runs/{id}/events`, `Accept: text/event-stream`. Generic SSE parser accepts named and unnamed events, deduplicates by sequenceNumber, reconnects with Last-Event-ID, and keeps at most 200 events in memory.                                        |
| Projection  | `GET /analysis-runs/{id}/canvas?view=BUSINESS&depth=2&levelOfDetail=2&minConfidence=0&onlyChanged=false`, plus optional `rootNodeId` and `search`. Search is debounced.                                                                                           |
| View enum   | `BUSINESS`, `DEVELOPER`, `DATA_OWNERSHIP`, `SECURITY`, `DATA_PIPELINE`, **`CONFIDENCE`**. The last tab is labelled Coverage. This matches the inspected GraphQueries enum.                                                                                        |
| Bounds      | Depth 1-5, detail 0-3, confidence 0-1. `onlyChanged` is server-side. Other checkboxes and analyzer/component/framework/layer filters apply to the loaded bounded projection, labelled accordingly.                                                                |
| Details     | `GET /semantic/nodes/{id}`. Displays properties, optional facts, assertions, enrichments, and reviews separately.                                                                                                                                                 |
| Evidence    | `GET /semantic/nodes/{id}/evidence` or `/semantic/edges/{id}/evidence`, only after selection. Source expiry uses optional `sourceAvailable:false`; retained provenance remains visible.                                                                           |
| Reviews     | `GET /projects/{id}/review-queue`; `POST /semantic/nodes/{id}/reviews` with `{decision,comment,editedTitle,editedDescription,mergeTargetId?}`. All six decisions supported. Merge requires a distinct valid UUID.                                                 |
| Diff        | `GET /projects/{id}/semantic-diff?fromAnalysisRun={id}&toAnalysisRun={id}`. Before/after values and evidence IDs are shown; links open the corresponding revision map with a stable-key search.                                                                   |
| Debug       | `GET /analysis-runs/{id}/{coverage,diagnostics,analyzer-plan,quarantined-facts,unresolved-symbols}`. Structured inspection, local search, pagination, and JSON export.                                                                                            |
| Layout      | `GET/PUT /analysis-runs/{id}/layout?view={enum}`. PUT sends `{positions:{[stableKey]:{x,y}},viewport:{x,y,zoom}}`. Manual drag and viewport changes persist after 700ms; saves serialize by run/view. A 404 means no saved layout; other failures remain visible. |
| Settings    | `GET /settings`; `PUT /settings` sends **only** `{aiMode,remoteAllowed,retentionDays}`. Modes: DISABLED/LOCAL_PROVIDER/REMOTE_PROVIDER; retention 1-365. Auth mode and capabilities are read-only.                                                                |

Loopback development uses no authorization header. The optional settings token
adds a Bearer header to REST and SSE requests. It lives only in Zustand memory,
never localStorage/sessionStorage. Only `sbm.locale` is stored in localStorage.

## UI and State

Shared tokens and UI primitives define the white/gray, charcoal, and teal
workspace; green, amber, and red indicate statuses with text/icons. RU/EN
resources are in `src/shared/lib/i18n.ts`. Data labels and API enums are preserved.
Set `localStorage['sbm.locale']='en'` before page initialization for stable English
acceptance labels, then use the Language control for RU verification.

Server state lives in TanStack Query. Zustand contains selection, filters,
positions, pins, drawer width, and other visual state only. Layout positions are
keyed by stable keys; the parent layout endpoint carries baseline positions to
new revisions. ELK computes compound data-ownership lanes in a dedicated worker.
React Flow node components are memoized. Monaco is lazy loaded, read-only, and
shows original evidence line numbers. The drawer can be resized with pointer or
arrow keys on its separator. Enter or Space on a focused graph node or edge
opens its evidence; closing the drawer restores focus to the selected element.
Diff selectors use completed analyses and reset when navigating to another run.

Routes: `/projects`, `/projects/:id`, `/projects/:id/analyses`,
`/projects/:id/review`, `/analyses/:id/canvas`, `/analyses/:id/diff`,
`/analyses/:id/debug`, and `/settings`.

## Verification Scope

Vitest/RTL tests exercise request contracts, failure handling, session-only
credentials, evidence retention, SSE framing, filtering, project creation,
baseline selection, and merge review validation. Browser tests use isolated,
explicit test transport fixtures from `src/test/fixtures.ts`; this module is
never imported into the application. Playwright verifies both 1440px and 390px
layouts, RU/EN states, actual ELK execution, nonoverlapping node geometry, local
Monaco rendering, evidence lazy loading, review submission, and layout saving.
Screenshots are written under `output/playwright/` and are intentionally ignored.

The parent owns `scripts/e2e.mjs` and live cross-stack acceptance. Frontend tests
do not claim successful repository ingestion or analyzer execution. The 2,000-node
interaction target and 10,000-node progressive-load benchmark need a separate
performance run against a populated API. Evidence IDs in diff responses have no
standalone lookup endpoint in this contract; the UI preserves the IDs and links
to the corresponding revision map instead of inventing an evidence endpoint.

See [PERFORMANCE.md](PERFORMANCE.md) for the bounded 1,000-node / 2,000-edge
acceptance, measurements, screenshots, image pin, and remaining performance
gate failure. The final image passed functional checks but exceeded the strict
heartbeat-delay limit on both viewports; an earlier production run passed it.
